# Differential validation contract 0.1.2

This version accompanies the pre-RC passive clarification, Validator A 0.1.0-draft.3, Validator B 0.1.2 and Corpus 0.1.2. Historical 0.1.1 contracts, oracles and results remain immutable.

Compare Base, normative capabilities, failed requirement IDs, NOT_TESTED IDs and operational status exactly on the same manifest-pinned bytes. Preserve experimental reporting and unknown authoritative claims. The reviewed oracle is authored from normative predicates and actual fixture bytes; neither validator is the oracle.

EPUBCheck 5.3.0 runs on every supplied corpus package, including native-invalid inputs and the bounded operational fixtures. Successful tool completion plus ERROR/FATAL establishes BASE-002 failure. Guarded specific IDs are additive. Warnings/information do not fail Base. Missing tool, crash, timeout or incomplete output produces TOOL_UNAVAILABLE and BASE-002 NOT_TESTED, without inventing document failure. Partial diagnostics from an incomplete process are not conformance evidence. A completed package run is recognized by the trusted tool completion record and expected exit semantics.

The external attribution data is REQUIREMENT_ATTRIBUTION_0.1.2.json. XML diagnostic attribution to SEM-002 is guarded by XHTML resource context; an OPF title error receives only BASE-002. Duplicate ID and XML structure are separate predicates. No diagnostic-code catch-all silently turns all errors into a specific native requirement.

PASS-001–003 and RS-001–002 retain their untested human/processor portions in NOT_TESTED. Deterministic document prohibitions can FAIL those groups or their SEC child predicates. Package Base PASS covers the implemented document predicate surface and completed inherited EPUB gate; it never certifies reader behavior, human static completeness or Accessible conformance. These five untested portions do not by themselves change the existing package aggregate to NOT_TESTED. Unresolved resource locality (SEC-008) does block package PASS.

Malformed container bytes that prevent inspection yield MALFORMED_INPUT and untested automatic predicates. An operational expansion/work ceiling yields RESOURCE_LIMIT. Unknown claims stay UNKNOWN. A completed external EPUB error may independently add BASE-002 even when native parsing was incomplete; operational status remains visible. This does not create a universal format maximum.

The resource-reference contract is spec/profiles/passive-resource-profile.md. Rust and Python implementations remain separate; only requirements, profiles, fixture/oracle data and attribution policy are shared. Validators do not mutate or sanitize source.
