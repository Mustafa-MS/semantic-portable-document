# Security policy

## Supported versions

SPD Format 0.1 RC1 is experimental. Security reports are accepted for the RC1 specification, validators, conformance corpus, and repository automation. No production-support or universal-security claim is made.

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue. Use GitHub’s private vulnerability reporting for this repository when available. If that channel is unavailable, contact the repository owner privately through the contact method shown on their GitHub profile and include “SPD security report” in the subject or first line.

Include the affected artifact or validator, impact, reproduction steps or a minimal package when safe, and any suggested mitigation. Avoid including unrelated personal data or secrets. You should receive acknowledgment within seven days; timelines for investigation and disclosure will depend on severity and reproducibility.

Ordinary hardening suggestions that do not describe an exploitable condition may use a public issue with the `security` label.
